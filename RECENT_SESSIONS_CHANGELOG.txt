  Date: 2026-06-08

           3 critical mobile input bugs sau khi migrate sang New Input System.

  File: Assets/2.Scripts/View/GamePlay/Tower/TDSlotHolderMainView.cs

  BUG-1: Ghost tạo ra ở vị trí 0,0,0 — user phải nhấc tay → tap lại mới drag được.
    Root cause: onClick fires on PointerUp → finger đã lifted → ghost tạo nhưng không
                còn touch nào active → drag không hoạt động.
    Fix: SetupOnSelectSlot() dùng EventTrigger.PointerDown thay vì onClick.
         Ghost tạo ngay khi finger down → drag tiếp luôn mà không cần nhấc tay.

  BUG-2: Ghost không follow finger khi ngón tay còn trên slot button.
    Root cause: Update() gọi IsPointerOverUI() trước UpdateGhostTransform()
                → khi finger trên UI, exit sớm, ghost đứng yên.
    Fix: Di chuyển UpdateGhostTransform() + RefreshRangeHighlights() lên TRƯỚC
         IsPointerOverUI() check. Ghost luôn follow, bất kể UI hay không.

  BUG-3: Cancel bị block khi nhấc tay trên slot button area.
    Root cause: IsPointerOverUI() return true → HandlePlacementInput() bị skip
                → TouchPhase.Ended không xử lý → ghost không cancel.
    Fix: Android: check fingerEnded trước IsPointerOverUI(). Nếu Ended thì
         vẫn cho HandlePlacementInput() chạy. Cancel/Place luôn được xử lý.
    Code:
      bool fingerEnded = dragTouch.HasValue && dragTouch.Value.phase == TouchPhase.Ended;
      if (!fingerEnded && IsPointerOverUI()) return;

  BUG-4: Ghost hiện DƯỚI ngón tay — bị che khuất, user không thấy.
    Root cause: Android touch point = bottom-center của fingertip. Camera isometric
                → finger che toàn bộ ghost.
    Fix: + const TOUCH_SCREEN_Y_OFFSET_RATIO = 0.10f
         GetFingerWorldPosition(): touchPos.y += Screen.height * 0.10f trước raycast.
         Ghost hiện phía trên ngón tay → visible.

  BUG-5: Phase 2 arm trong cùng frame cellChanged → auto-trigger direction ngay.
    Root cause: m_PhaseArmed = true set ngay cả khi cellChanged = true.
                Frame sau: ngón tay ra ngoài threshold → Phase 2 trigger tức thì.
    Fix: Guard: if (!cellChanged && insideThreshold) m_PhaseArmed = true.
         Phải vào threshold zone ít nhất 1 frame KHÔNG cellChanged mới arm được.

  SESSION 56 — ANDROID MOBILE INPUT SYSTEM (PHASE 2) + GOLD RATE       [✅ DONE]

  Date: 2026-06-08

  File: Assets/2.Scripts/View/GamePlay/Tower/TDSlotHolderMainView.cs

  BUG-6: Ghost auto-place trong khi user đang drag (finger chưa nhấc).
    Root cause A (ban đầu nghĩ): multi-touch — ngón tay thứ 2 chạm, activeTouches[0]
                bị re-order → Ended ngón phụ trigger placement.
    Root cause B (confirmed sau khi user xác nhận test 1 finger):
      Android micro-lift: cảm biến capacitive mất tiếp xúc ngắn (~ms) trong lúc drag
      chậm → TouchPhase.Ended fire → m_IsDirectionSelected=true → placement xảy ra.
      Sensor lấy lại tín hiệu ngay → TouchPhase.Began → ngón tay "vẫn đang chạm".

    Fix A — Finger ID locking (giữ để handle edge case re-order):
      + field int m_DragFingerId = -1
      + helper Touch? FindDragTouch(): tìm touch theo touchId, fallback activeTouches[0]
      + Update(): capture m_DragFingerId = activeTouches[0].touchId khi = -1
      + Tất cả touch reads (UpdateGhostTransform, GetFingerWorldPosition,
        HandlePlacementInput, IsPointerOverUI) dùng FindDragTouch() thay activeTouches[0]
      + Reset m_DragFingerId = -1 tại OnCreateTower(), CancelPlacement(), OnPlaceTowerSuccess()

    Fix B — Minimum Phase 2 duration (lọc micro-lift):
      + const MIN_PHASE2_DURATION = 0.20f
      + field float m_DirectionSelectedTime = -999f
      + Khi m_IsDirectionSelected set = true lần đầu: ghi m_DirectionSelectedTime = Time.unscaledTime
      + HandlePlacementInput(): chỉ place nếu Time.unscaledTime - m_DirectionSelectedTime >= 0.20f
        Nếu Ended < 0.20s sau Phase 2 start → CancelPlacement() thay vì place

  BUG-7: Ghost auto-trigger Phase 2 khi drag qua valid cell (tower zone / path cell).
    Root cause: Khi drag liên tục qua cell, sequence xảy ra:
      1. cellChanged → PhaseArmed=false
      2. Vài frame sau: finger qua center → insideThreshold=true → PhaseArmed=true
      3. Finger tiếp tục di chuyển → !insideThreshold + cellOk → Phase 2 trigger!
      Trên path cell: cellOk=false (tower không valid trên path) → không bị.
      Trên tower zone: cellOk=true → bị. Tương tự operator trên path cell.

    Fix — Minimum cell hold duration:
      + const MIN_CELL_HOLD_DURATION = 0.35f
      + field float m_CellEnterTime = -999f
      + Khi cellChanged: m_CellEnterTime = Time.unscaledTime
      + Arm condition: if (!cellChanged && insideThreshold
                           && Time.unscaledTime - m_CellEnterTime >= 0.35f)
                           m_PhaseArmed = true
      → Drag qua nhanh (<0.35s trên cell): không arm, Phase 2 không trigger
      → Dừng ≥0.35s tại center rồi swipe: arm → Phase 2 → direction selection ✅

  - TDGameEventBus: VFX/Audio/UI decoupled hoàn toàn khỏi gameplay
  - Strategy Pattern: IGateAssignmentStrategy (4 impl), IOperatorBehavior (2 impl)
  - Flyweight: TDFlyweightEnemyDataSettings — data không alloc mỗi frame
  - Object pooling: Unity ObjectPool<T> cho enemy, Queue<GO> cho VFX, AudioSource[] cho SFX
  - Data-driven SO: Stage/Tower/Enemy/Operator/Effect config — không hardcode
  - CancellationToken trong async wave loop — ít dev làm đúng điều này
  - IPathFinder inject qua constructor (DIP) — TDMazePathGenerator không biết A* impl

  [NỢ KỸ THUẬT]

  ── ALGORITHMS (summary) ─────────────────────────────────────────────────────

  Recursive Backtracker (iterative Stack) → maze generation O(w×h)
  A* Manhattan heuristic, 4-dir, List openSet → O(n²) hiện tại
  Multi-path extraction via interior cell blocking → k paths, k = CONFIG_NUM_PATHS
  TDOffsetRangeDTO RotateOffset: discrete 2D rotation matrix theo 4 cardinal dirs
  PathProgress (0→1): enemy ưu tiên theo tiến độ trên path (focus-fire nearest-to-end)
  DifficultyRatioTable: lookup O(1), Distribute() → Fisher-Yates shuffle wave
  PauseAwareDelay: poll Time.deltaTime (bị timeScale affect) thay Task.Delay wall-clock
