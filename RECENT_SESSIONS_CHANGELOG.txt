  Date: 2026-06-02

  ── Bug report ───────────────────────────────────────────────────────────────

  "Lâu lâu place tower hoặc operator xong button retreat tự display luôn"
  → Không phải mọi lần, chỉ đôi khi (race condition).

  ── Root cause ───────────────────────────────────────────────────────────────

  Cùng 1 frame khi user thả ngón/click để đặt unit:
    1. TDSlotHolderMainView.Update() chạy trước → Instantiate tower/operator
       → BoxCollider active ngay lập tức
    2. TDOperatorSelectionView.Update() chạy sau → HandleTapInput() nhận
       cùng input event → Physics.Raycast hit unit vừa Instantiate
       → SelectOperator() / SelectTower() → show retreat panel

  Thứ tự Update() phụ thuộc Script Execution Order → intermittent (lâu lâu)
  vì chỉ xảy ra khi TDSlotHolderMainView chạy trước TDSelectionView.

  ── Fix ──────────────────────────────────────────────────────────────────────

  [MODIFIED] TDSlotHolderMainView.cs
    + public static bool IsPlacingUnit { get; private set; }
    Set = true  : khi ghost Instantiate (bắt đầu placement)
    Set = false : khi đặt thành công (m_CurrentTower = null sau place)
    Set = false : khi CancelPlacement() (cancel hoặc nhấc ngón sớm)

  [MODIFIED] TDOperatorSelectionView.cs — HandleTapInput():
    + if (TDSlotHolderMainView.IsPlacingUnit) return;
    → Guard ngay sau "if (!tapped) return", trước IsPointerOverUI check
    → Khi placement mode active → SelectionView bỏ qua toàn bộ tap input

  ── Result ───────────────────────────────────────────────────────────────────
    ✅ Retreat panel không còn tự hiện sau khi đặt tower/operator
    ✅ Fix không ảnh hưởng tap selection bình thường (flag false khi idle)
