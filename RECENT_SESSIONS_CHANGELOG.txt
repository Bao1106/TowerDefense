  SESSION 54 — BUG FIX: RANGER ATTACK RANGE (OVERLAPSHPERE → CELL-BASED)  [✅ DONE]
════════════════════════════════════════════════════════════════════════════════

  Date: 2026-06-06

    → hình tròn vô hướng, không quan tâm facing direction
    → TDOffsetRangeDTO (dùng cho highlight) là directional cell offsets
    → 2 hệ thống khác nhau hoàn toàn

    → PathCellOperatorBehavior nhận rotation nhưng không dùng → ISP violation
    → new TDOffsetRangeDTO() mỗi frame → allocation trong hot path

  Fix v2 (đúng):

  [MODIFIED] IOperatorBehavior.cs
    TryAttack(cell, worldPos, OperatorData)   — bỏ rotation param
    ExecuteHit(cell, worldPos, OperatorData)  — bỏ rotation param

  [MODIFIED] TowerZoneOperatorBehavior.cs
    + field Transform        m_OperatorTransform  (cache trong OnInit)
    + field TDOffsetRangeDTO m_RangeDTO           (cache trong OnInit — không alloc mỗi frame)
    OnInit(): m_OperatorTransform = view.transform; m_RangeDTO = new TDOffsetRangeDTO(rangeOffsets)
    TryAttack(): dùng m_RangeDTO.GetCellsInRange(cell, m_OperatorTransform.rotation)
                 + scan TDEnemyRegistry.GetAll() — cùng logic với range highlight
    OnRemove(): m_OperatorTransform = null

  [MODIFIED] PathCellOperatorBehavior.cs — bỏ rotation param (không đổi logic)
  [MODIFIED] TDOperatorView.cs — bỏ transform.rotation khỏi TryAttack/ExecuteHit calls

  Behavior tự quản lý rotation qua Transform reference → caller không cần biết.
  Visual range = actual attack range (dùng chung TDOffsetRangeDTO).
