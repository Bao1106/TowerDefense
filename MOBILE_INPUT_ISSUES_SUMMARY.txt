KIẾN TRÚC INPUT HIỆN TẠI (Android)
────────────────────────────────────────────────────────────────────────────────

Toàn bộ mobile input được xử lý bằng POLLING trong Update() — không dùng
Unity Input System event-driven. #if UNITY_ANDROID chia 2 branch tại điểm
đọc raw touch, sau đó hội tụ về cùng TDUserInputControl event bus.

── Luồng đặt tower ──────────────────────────────────────────────────────────

  [1] User tap slot button
        UI Button.onClick
          → TDTowerMainControl.OnSelectTowerHolder(index)
          → onGetTowerPrefab.Invoke(slot)
          → TDSlotHolderMainView.OnCreateTower(slot)   ← Instantiate ghost

  [2] User drag ngón trên map (mỗi frame)
        Update()
          → IsPointerOverUI()        ← RaycastAll tại GetTouch(0).position
              true  → return (block toàn bộ)
              false → tiếp tục
          → UpdateGhostTransform()
              GetFingerWorldPosition() ← Physics.Raycast GetTouch(0), no LayerMask
              Phase 1 (!m_IsDirectionSelected):
                snap ghost đến nearest cell
                delta > threshold → Phase 2 entry
              Phase 2 (m_IsDirectionSelected):
                cập nhật rotation theo hướng ngón
                delta < threshold → thoát Phase 2
          → HandlePlacementInput()
              TouchPhase.Ended:
                m_IsDirectionSelected true  → OnMouseButton0Clicked() → place
                m_IsDirectionSelected false → CancelPlacement()

  [3] Place thành công
        TDUserInputControl.OnMouseButton0Clicked()
          → onMouseButton0Clicked.Invoke(true)
          → TDSlotHolderMainView.OnMouseButton0Clicked(true)
          → TDTowerMainControl.OnPlaceTower(ghost)
          → TDPlaceTowerControl.CheckPlaceTower()
          → onPlaceTowerSuccess.Invoke(true)
          → SpendGold, Destroy ghost, cleanup

  [4] Cancel
        Cancel button onClick
          → TDUserInputControl.OnMouseButton1Clicked()
          → CancelPlacement() ← Destroy ghost, HideHighlights, HidePanel

── Luồng chọn unit đã đặt (TDOperatorSelectionView) ────────────────────────

        Update()
          → HandleTapInput()
              TouchPhase.Began → screenPos = GetTouch(0).position
              guard IsPlacingUnit → skip (không select khi đang drag ghost)
              guard IsPointerOverUI() → skip
              Physics.Raycast(ray) → hit
                → TDOperatorView    → SelectOperator()
                → TDTowerWeaponView → SelectTower()
                → miss              → Deselect()

── Điểm mấu chốt ────────────────────────────────────────────────────────────

  TDUserInputControl là thin event bus — không có logic, chỉ forward:
    OnMouseButton0Clicked() → onMouseButton0Clicked?.Invoke(true)
  Desktop và Mobile đều đi qua cùng event bus.
  Sự khác biệt platform chỉ nằm ở AI trigger event (GetMouseButtonDown vs
  TouchPhase.Ended), không phải downstream logic.

  Tất cả bugs INPUT-02 → INPUT-08 nằm trong khoảng:
    "đọc touch raw" → "fire event bus"
  Cụ thể tại: GetFingerWorldPosition(), UpdateGhostTransform(),
               HandlePlacementInput(), OnCreateTower(), IsPointerOverUI().

[INPUT-02] Ghost tower không follow finger
────────────────────────────────────────────────────────────────────────────────
Severity: HIGH
Status: PENDING

Root cause:
  GetFingerWorldPosition() dùng Physics.Raycast không có LayerMask.
  Ray từ camera bắn qua vị trí ngón → hit first collider gặp trên đường ray.

  NOTE — ghost collider KHÔNG phải nguyên nhân chính:
    Ghost nằm ngay trên ground tile đang snap vào → ghost x,z ≈ ground x,z
    Dù ray hit ghost surface (y=0.6) hay ground (y=0), GetNearestGridPosition chỉ
    dùng x,z → trả về cùng cell → ghost vẫn follow đúng.
    Bug này xảy ra tương tự trên Editor nhưng KHÔNG gây ra triệu chứng.

  Nguyên nhân thực sự trên Android — placed tower và enemy collider:
    Placed tower: đã đặt trên map, có Collider ở vị trí x,z khác với ngón tay
    Enemy: di chuyển liên tục trên map trong khi user đang drag ghost
    → Ray từ ngón tay hit enemy/placed tower ở cell khác
    → hit.point = vị trí enemy/tower → GetNearestGridPosition trả về cell sai
    → ghost nhảy sang cell enemy/tower đang đứng

  Tại sao Editor ít bị:
    Mouse pixel-perfect + thấy rõ con trỏ → dễ tránh enemy/tower
    Test thường ít enemy, kiểm soát timing
    Trên Android: ngón tay che ~10mm, enemy chạy liên tục → hit sai thường xuyên

  Root cause thứ 2: Ghost = Instantiate(slot.prefab) → có Collider của tower thật.
  Disable collider (INPUT-06) giúp loại bỏ 1 nguồn hit nhầm.

Fix:
  Option A — Unity Layer (cần Editor setup):
    1. Tạo layer "Ground", assign cho tất cả tile khi BuildGridZones():
         tileGO.layer = LayerMask.NameToLayer("Ground");
    2. Chỉ raycast hit Ground layer:
         private static readonly int GROUND_MASK = LayerMask.GetMask("Ground");
         Physics.Raycast(ray, out hit, Mathf.Infinity, GROUND_MASK)

  Option B — Plane.Raycast (không cần Editor setup):
    Thay Physics.Raycast bằng raycast xuống plane y=0:
         var plane = new Plane(Vector3.up, Vector3.zero);
         if (plane.Raycast(ray, out float dist))
             return ray.GetPoint(dist);

  INPUT-06 (disable collider trên ghost) bổ trợ cho cả 2 option.

[INPUT-03] Ghost spawn tại (0,0,0) thay vì vị trí ngón tay
────────────────────────────────────────────────────────────────────────────────
Severity: HIGH
Status: PENDING

Root cause:
  Frame N:   User tap slot button
             → Button.onClick fired → OnCreateTower() → Instantiate tại Vector3.zero
             → m_TowerCreatedThisFrame = true
  Frame N+1: m_TowerCreatedThisFrame guard → Update() early return hoàn toàn
             → Ghost vẫn ở (0, 0, 0), không ai di chuyển nó
  Frame N+2: User nhấc ngón (xong tap button) → touchCount = 0
             → GetFingerWorldPosition(): touchCount = 0
             → fallback sang Input.mousePosition
             → trên Android, mousePosition = stale vị trí touch trước đó (slot button area)
             → ghost bị đẩy về vị trí slot button, không phải map

  User phải tap lại lên map → touchCount = 1 → ghost mới bắt đầu follow.
  Flow trực quan bị phá: "tap slot → drag lên map ngay" không hoạt động.

Fix:
  Spawn ẩn off-screen nếu chưa có touch, frame tiếp theo khi drag lên map mới hiện:
    m_TrackingFingerId = -1; // reset để GetTrackedTouch() lấy touch mới
    Vector3 spawnWorld = GetFingerWorldPosition();
    Vector3 spawnPos   = spawnWorld != Vector3.negativeInfinity
        ? new Vector3(spawnWorld.x, TDConstant.CONFIG_TOWER_PLACE_Y, spawnWorld.z)
        : new Vector3(0f, -999f, 0f); // ẩn off-screen nếu không có touch
    m_CurrentTower = Instantiate(slot.prefab, spawnPos, Quaternion.identity);
    m_LastSnappedPos = spawnPos;

[INPUT-04] Auto place khi drag — m_IsDirectionSelected không reset khi đổi cell
────────────────────────────────────────────────────────────────────────────────
Severity: HIGH
Status: PENDING

Root cause:
  Khi drag ghost từ slot bar (bottom UI) lên map, khoảng cách di chuyển lớn >>
  threshold (35% cellSize ≈ 0.7u) → m_IsDirectionSelected = true ngay tại cell đầu tiên.
  User nhấc ngón → place ngay, không có cơ hội chọn direction.

  Nuance quan trọng về code flow:
    Khi m_IsDirectionSelected = true, UpdateGhostTransform() early return ở dòng 103
    (return trong Phase 2 block) → không bao giờ chạy đến đoạn snap check bên dưới.
    → Không có chỗ nào reset m_IsDirectionSelected khi đổi cell trong Phase 2.
    → Fix phải đặt tại Phase 1 snap check (khi snappedPosMobile != m_LastSnappedPos),
      không thể đặt trong Phase 2 block.

  Comment trên field khai báo ghi "Reset về false khi ghost di chuyển sang cell mới"
  nhưng UpdateGhostTransform() chưa implement.

Fix (1 dòng):
  if (snappedPosMobile != m_LastSnappedPos)
  {
      m_LastSnappedPos      = snappedPosMobile;
      m_IsDirectionSelected = false; // THÊM DÒNG NÀY
  }

[INPUT-05] Race condition: Phase 2 trigger và place trong cùng 1 frame Ended
────────────────────────────────────────────────────────────────────────────────
Severity: HIGH
Status: PENDING

Root cause:
  Unity giữ nguyên touch position của TouchPhase.Ended trong frame đó.
  Thứ tự trong Update() frame Ended:
    UpdateGhostTransform()  ← chạy TRƯỚC
      → nhận Ended position (Unity vẫn giữ)
      → tính delta = fingerWorld - m_LastSnappedPos
      → nếu delta > threshold → m_IsDirectionSelected = true  ← Phase 2 entry
    HandlePlacementInput()  ← chạy SAU trong cùng frame
      → thấy TouchPhase.Ended + m_IsDirectionSelected = true
      → gọi OnMouseButton0Clicked() → place

  Kết quả: Phase 2 được trigger VÀ tower được đặt trong cùng 1 frame.
  User không có frame nào để "ở Phase 2 mà không bị place ngay".
  Tower đặt theo hướng ngón tay tại thời điểm nhấc lên, không intentional.

Fix (1 dòng đầu mobile branch trong UpdateGhostTransform):
  if (Input.touchCount > 0 && Input.GetTouch(0).phase == TouchPhase.Ended) return;

[INPUT-06] Ghost dùng cùng prefab với placed tower — scripts gameplay chạy uninit
────────────────────────────────────────────────────────────────────────────────
Severity: MEDIUM
Status: PENDING

Root cause:
  Instantiate(slot.prefab) kích hoạt toàn bộ MonoBehaviour trên prefab.
  Ghost không được Init() → TDOperatorView.Update() gọi GetData() với uninit data
  → NullReferenceException tiềm ẩn.
  Collider active → chặn raycast (liên quan INPUT-02).
  HP bar hiện trên ghost đang drag → bug UX.

Fix:
  Disable gameplay components ngay sau Instantiate:
    var unit = m_CurrentTower.GetComponent<IPlacedUnit>() as MonoBehaviour;
    if (unit != null) unit.enabled = false;
    foreach (var col in m_CurrentTower.GetComponentsInChildren<Collider>())
        col.enabled = false;

[INPUT-07] fingerId không được track — GetTouch(0) sai ngón khi multi-touch
────────────────────────────────────────────────────────────────────────────────
Severity: MEDIUM
Status: PENDING

Root cause:
  Hard-code GetTouch(0). Unity không đảm bảo touch index stable giữa các frame.
  Khi user vô tình chạm 2 ngón, index 0 có thể đổi → ghost nhảy loạn.

Fix:
  Track fingerId từ TouchPhase.Began:
    private int m_TrackingFingerId = -1;

    Touch? GetTrackedTouch() {
        for (int i = 0; i < Input.touchCount; i++)
            if (Input.GetTouch(i).fingerId == m_TrackingFingerId)
                return Input.GetTouch(i);
        if (m_TrackingFingerId == -1 && Input.touchCount > 0) {
            m_TrackingFingerId = Input.GetTouch(0).fingerId;
            return Input.GetTouch(0);
        }
        return null;
    }

[INPUT-08] TouchPhase.Ended bị bỏ qua nếu IsPointerOverUI guard return cùng frame
────────────────────────────────────────────────────────────────────────────────
Severity: MEDIUM
Status: PENDING

Root cause:
  TouchPhase.Ended chỉ tồn tại đúng 1 frame. Cấu trúc Update() hiện tại:
    if (IsPointerOverUI()) return;   // nếu true trong frame Ended → return sớm
    HandlePlacementInput();          // không bao giờ chạy → Ended bị mất vĩnh viễn

  Kịch bản: User nhấc ngón gần Cancel button → IsPointerOverUI() = true
  → Ended bị skip → ghost không place, không cancel → ghost treo vô hạn.

Fix:
  Tách HandlePlacementEnded() ra gọi TRƯỚC IsPointerOverUI guard:
    private void Update()
    {
        if (m_CurrentTower == null) return;
        if (m_TowerCreatedThisFrame) { m_TowerCreatedThisFrame = false; return; }

        HandlePlacementEnded(); // Ended TRƯỚC guard

        if (IsPointerOverUI()) return;
        UpdateGhostTransform();
        RefreshRangeHighlights();
        HandlePlacementInput(); // chỉ handle Began/Moved
    }

────────────────────────────────────────────────────────────────────────────────
Severity: LOW

INPUT SYSTEM — LEGACY vs NEW
────────────────────────────────────────────────────────────────────────────────

Project setting: activeInputHandler = 2 (Both) — cả 2 pipeline đang active.
Package: com.unity.inputsystem 1.11.2 đã cài, chưa dùng ở đâu.
Code hiện tại: 100% Legacy Input Manager (chỉ tập trung tại 2 file).

── Legacy Input Manager ─────────────────────────────────────────────────────

  Built-in, không cần package. API tĩnh toàn cục: Input.GetTouch(), Input.mousePosition.
  Cơ chế: POLLING — Unity snapshot input 1 lần đầu frame, code đọc snapshot đó.

  Vấn đề cốt lõi:
    - TouchPhase.Ended tồn tại đúng 1 frame → mất nếu frame đó bị early return (INPUT-08)
    - GetTouch(0) index không stable khi multi-touch (INPUT-07)
    - Input.mousePosition trên Android = stale position của touch trước (INPUT-03, INPUT-09)
    - Không có fingerId tracking built-in

── New Input System ─────────────────────────────────────────────────────────

  Package riêng. Hỗ trợ cả event-driven lẫn polling (EnhancedTouch).
  Cơ chế: Buffer tất cả input event trong queue → không bao giờ mất event dù early return.

  API khác biệt:
    Legacy                          New Input System
    Input.touchCount > 0            Touch.activeTouches.Count > 0
    Input.GetTouch(0).phase         touch.phase (UnityEngine.InputSystem.TouchPhase)
    Input.GetTouch(0).position      touch.screenPosition
    Input.mousePosition             Mouse.current.position.ReadValue()
    Input.GetMouseButtonDown(0)     Mouse.current.leftButton.wasPressedThisFrame
    Input.GetMouseButtonDown(1)     Mouse.current.rightButton.wasPressedThisFrame
    Input.GetKeyDown(KeyCode.E)     Keyboard.current.eKey.wasPressedThisFrame
    Input.GetKeyDown(KeyCode.Q)     Keyboard.current.qKey.wasPressedThisFrame

  Cần enable ở Start()/OnEnable():
    UnityEngine.InputSystem.EnhancedTouch.EnhancedTouchSupport.Enable();

── Scope migration nếu chọn New Input System ────────────────────────────────

  Files phải sửa: CHỈ 2 file
    TDSlotHolderMainView.cs     — 9 chỗ dùng Legacy
    TDOperatorSelectionView.cs  — 4 chỗ dùng Legacy

  Không đụng:
    TDUserInputControl (event bus), TDTowerMainControl, TDPlaceTowerControl,
    IsPointerOverUI() RaycastAll, tất cả gameplay logic downstream,
    toàn bộ #if UNITY_ANDROID guard.

  Lợi ích migration:
    - INPUT-07 (fingerId) resolved tự động — EnhancedTouch track theo fingerId
    - INPUT-08 (Ended bị mất) resolved — buffer đảm bảo không mất event
    - Không cần workaround thủ công cho 2 issue trên

  Rủi ro: thấp — scope nhỏ, downstream không đổi.
